二 · 新能力：mousewheel 滚轮翻页

我发给 AI 的提问：

Swiper 6 想让鼠标滚轮翻页怎么配？它和已有的 loop 循环、autoplay 自动播放会冲突吗？另外怎么防止光标放在轮播上时页面就没法滚动了？

AI 给出的配置（节选）：

mousewheel: {
  releaseOnEdges: true,   // AI 建议：到头了把滚轮还给页面
}

亲手验证 + 翻源码后发现 AI 的建议不对：

AI 说"到头了会把滚轮还给页面"，但在 loop 循环模式下这是无效药方——翻开 Swiper 6.8.4 源码 mousewheel.js 第 382~386 行：if (swiper.isEnd && !swiper.params.loop && params.releaseOnEdges)，条件里明确排除了 loop；循环模式永远不存在"到头"。我的修改：把 releaseOnEdges 显式写成 false 并加注释说明原因，防止以后误读。

最终写入页面的配置（初始化与销毁重建两处都加了）：

mousewheel: {
  invert: false,        // 滚轮向下 = 翻下一张（自然方向）
  forceToAxis: false,   // 不锁定轴向，普通鼠标竖向滚轮即可翻页
  releaseOnEdges: false,// loop 模式没有"边缘"，此项无效，显式声明防误读
},
验证结论（本地 Swiper 6.8.4 自动化实测，5 项全过）：① 悬停轮播滚轮向下连续翻下一张；② 向上滚回上一张；③ 第 6 张再往下滚循环回第 1 张；④ 光标移到轮播外滚轮正常滚动页面（源码 mouseEntered 判断接管范围，不会劫持全页）；⑤ 无控制台报错。

三 · 答辩四连问 · 自答

问 1：这段代码什么意思？
答：mousewheel 模块监听轮播容器上的滚轮事件，把滚轮增量换算成"上一张 / 下一张"。invert 控制方向；forceToAxis 决定是否只认滚轮的轴向增量；接管范围由源码里的 mouseEntered 判断——光标悬停在轮播上才接管，移开就还给大家。

问 2：AI 第一次给的哪里不对，你改了什么？
答：AI 建议加 releaseOnEdges: true 防止"劫持页面"，但我们的轮播是 loop 循环模式——源码里该逻辑被 !swiper.params.loop 短路，永远不生效。我把它改成显式 false 并写注释说明：防劫持靠的不是这个参数，而是 mouseEntered 的悬停判断。

问 3：新参数的作用？
答：invert——滚轮方向取反（滚下变翻上一张）；forceToAxis——锁定按滚轮轴向判断，避免触控板斜向手势误翻；releaseOnEdges——非循环轮播滚到头后放行页面滚动，loop 模式下无效。

问 4：现场把 delay 改成指定值会怎样？
答：以 3200 → 1600 为例：autoplay.delay 是每张停留的毫秒数，减半后自动翻页频率提高一倍，大约每 1.6 秒翻一张；speed: 800 的动画时长不变，所以节奏更紧凑；滚轮手动翻页与 delay 无关，不受影响。
