任务一 · 提示词工程师

目标：让 AI 听懂需求，生成 new Swiper('#wySw4', {...}) 配置 —— ① 无缝循环 ② 3.2 秒自动翻页且手动操作后不停止 ③ 圆点分页器可点击 ④ 初始效果 cube。共两轮迭代，每轮保留提示词与 AI 回答。

第 1 轮：第一版提示词（有遗漏）

我发出的提示词：

帮我用 Swiper 6 写一个轮播配置：容器是 #wySw4，要能无缝循环播放，每 3.2 秒自动翻一次页，底下要有圆点分页器，切换效果用 cube 立方体。

AI 的回答（代码）：

new Swiper('#wySw4', {
  loop: true,                 // 无缝循环 ✓
  autoplay: { delay: 3200 },  // 自动翻页 ✓（但漏了不停止的要求）
  pagination: { el: '#wyPag4' },  // 圆点 ✓（但不可点击）
  effect: 'cube',             // 立方体 ✓
});

亲手粘进页面验证发现的问题：

① 手动拖动或点圆点后，轮播就永远停了——AI 没写 disableOnInteraction: false；② 圆点点了没反应——AI 没写 clickable: true；③ 没写 speed，翻页瞬间完成，看不出 cube 的旋转过程。

第 2 轮：说清楚需求后的修正版

我发出的提示词（把验收标准逐条写进提示词）：

上一版有三个问题。请严格按这四条验收标准重新给 Swiper 6 的 #wySw4 配置：① loop 无缝循环，最后一张往后翻直接回到第一张；② autoplay delay 3200，且必须加 disableOnInteraction: false——人拖动、点圆点之后也要继续自动翻；③ 分页器圆点必须 clickable: true，点第几个圆点跳第几张；④ effect: 'cube' 初始就是立方体，speed 给 800 让旋转看得清。请逐条对照，一条都不能少。

AI 的回答（代码）：

new Swiper('#wySw4', {
  effect: 'cube',             // ④ 初始立方体 ✓
  speed: 800,                 // 翻页动画 800ms，旋转看得清 ✓
  loop: true,                 // ① 无缝循环 ✓
  autoplay: {
    delay: 3200,              // ② 每 3.2 秒自动翻页 ✓
    disableOnInteraction: false,  // ② 手动操作后继续自动翻 ✓
  },
  pagination: {
    el: '#wyPag4',
    clickable: true,          // ③ 圆点可点击跳转 ✓
  },
  grabCursor: true,           // 手型光标，提示可拖动（附加）
});

答辩抽问 · 自答

问：你的第一版提示词漏掉了哪个需求？

答：漏了"手动操作后不停止"和"圆点可点击"这两条行为细节。第一版只描述了"有什么"（圆点、自动翻），没描述"怎么表现"（点了要有反应、拖完要继续翻）。

问：你是怎么在第二轮里"说清楚"的？

答：把模糊的形容词换成可验证的参数名——"不停止"写成 disableOnInteraction: false，"圆点能点"写成 clickable: true，并声明"逐条对照、一条不能少"，让 AI 按验收清单自检。

问：AI 第一次给的代码错在哪？

答：不是语法错，是行为错——autoplay 缺 disableOnInteraction: false（Swiper 默认交互后停止）、pagination 缺 clickable: true（默认只作指示不可点）、没配 speed 导致 cube 动画几乎看不见。语法正确的代码也会"不听话"，需求必须精确到参数。

任务二 · creative 仿写「电影墙」

目标：跟 AI 读懂官方 creative 示例 257，仿写一个"电影墙"切换：上一张缩小、左移并带角度退场，下一张放大、从右侧进场；并回答两个追问。

第一步：跟 AI 读示例 257 的要点

提问要点：creativeEffect 里 prev 是"正在离开的上一张"怎么退场，next 是"还没登场的下一张"从哪进来；translate 是 [X, Y, Z] 三轴位移，rotate 是 [绕X, 绕Y, 绕Z] 三轴旋转。

AI 拆解后我采用的仿写配置（已加入上方任务四第 7 个按钮「creative 电影墙」）：

creativeEffect: {
  limitProgress: 2,           // 上下各保留 2 张参与演出
  prev: { translate: ["-120%", 0, -240], rotate: [0, 0, -8], opacity: 0.3, scale: 0.85 },  // 缩小·左移·带角度离场
  next: { translate: ["120%", 0, -120],  rotate: [0, 0,  8], opacity: 0.5, scale: 1.15 },  // 放大·右移进场
}

追问一（自己的话）：prev / next 分别是什么

prev 是正在离开的一张：它往左挪出视野、缩小到 85%、带 -8° 轻微倾斜、透明度降到 0.3——"退场的演员往侧幕走"。next 是还没登场的下一张：从右外侧以放大到 115% 的姿态、带 +8° 反向倾斜压进来，透明度 0.5 起步——"下一幕从台侧迎面压上"。一退一进合成"电影墙"整场戏。

追问二（自己的话）：translate 的百分号是相对什么的

相对 slide 自身尺寸：X 方向的 120% 等于"挪动一张自己的宽度"，Y 方向按高度算——所以任何屏幕宽度下位移比例都一致。为验证，我做了 rotate ±20 度实验：把两个 rotate 的第三个数字从 ±8 改成 ±20，实测倾斜明显变陡，其余表现不受影响，说明第三个数字就是绕 Z 轴的平面旋转角。

答辩抽问 · 自答

问：你的仿写和原示例差在哪、为什么这么改？

答：原示例 257 的 prev 是平移淡出，我把 prev 加了 rotate ±8 和 scale 0.85，next 加 scale 1.15，做出"一退一进"的方向感；limitProgress 收到 2 保证演出只有相邻两张参与，画面不乱。

问：如果想让下一张从底部进场，改哪个参数？

答：改 next 的 translate 第二个值，如 ["0%", "120%", 0]，Y 轴 120% 即从自身高度下方压上来；rotate 保持 0 就是纯上滑。

第二步：课堂没讲的能力 —— mousewheel 滚轮翻页

我发出的提问：

我想让光标放在轮播上时滚动鼠标滚轮就能翻页，移开滚轮要能正常滚动网页，怎么办？循环模式下要注意什么？

AI 给出的核心配置（已写入本页底部 JS 的初始化与销毁重建两处）：

mousewheel: {
  forceToAxis: false,     // 不区分滚轮方向轴
  releaseOnEdges: true,   // ← AI 建议加这个防止"劫持页面"
  invert: false,          // 向下滚动 = 翻下一张
}

AI 翻车实录（有源码证据）

AI 建议 releaseOnEdges: true 来防止滚轮"劫持页面"，但我查阅 Swiper 6.8.4 源码 mousewheel.js 第 382~386 行发现：该逻辑被 !swiper.params.loop 短路——循环模式下永远"到不了头"，这个参数等于没写，AI 的建议是无效药方。我的修正：显式写 releaseOnEdges: false 并加注释说明原因，防止后人误读。

本地自动化实测（Swiper 6.8.4）5 项全过：滚轮下翻 / 上翻 / 第 6 张循环回第 1 张 / 光标移出后页面照常滚动（不劫持）/ 无控制台报错。

答辩四连问 · 自答

问：mousewheel 是怎么工作的？

答：Swiper 在容器上监听 wheel 事件，光标悬停时 mouseEntered 置真，滚动 delta 累计超过阈值就调 slideNext/slidePrev；悬停期间事件被接管，页面不滚。

问：AI 错在哪？你改了什么？

答：AI 建议 releaseOnEdges: true 防"劫持"，但循环模式下源码短路了该逻辑，参数无效。我显式写 false 并注释原因；实测确认移开光标后页面滚轮立刻恢复，无需依赖该参数。

问：forceToAxis / releaseOnEdges / invert 分别管什么？

答：forceToAxis 只认主滚动轴（配合横向滚轮板）；releaseOnEdges 让"到头时把滚轮还给页面"（循环模式下失效）；invert 反转滚轮方向。

问：把 delay 3200 改成 1600 会有什么变化？

答：自动翻页频率翻倍（约 1.6 秒一张），speed 动画时长不变所以每帧观感一致；滚轮手动翻页不受 delay 影响。
